## Supervised Learning Setup


Let's start with some terminology

### Hypothesis/Prediction function:
A function
$$
h : \mathcal{X} \mapsto \mathcal{Y}
$$

- $\mathcal{X}$ is an image, and $\mathcal{Y}$ contains "cat" or "not"
- $\mathcal{X}$ is a text snippet, and $\mathcal{Y}$ contains "hate speech" or "not"
- - $\mathcal{X}$ is house data, and $\mathcal{Y}$ could be the price


### Training set
Set of pairs 
$$
\{(x^{(i)}, y^{(i)}); i = 1, \ldots, n\}
$$

s.t $x^{(i)} \isin \mathcal{X}$ and $y^{(i)} \isin \mathcal{Y}$ for $i=1,...,n$

**Given a training set our goal is to produce a *good* prediction function $h$**
- Defining "good" is a modeling question
- We will want to use $h$ on new data, not on the trainign set

### Reminder
- If $y$ is continuous, then it is called a *regression* problem
- If $y$ is discrete, then it is called a *classification* problem

How do we represent $h$?
One popular choice is an *affine function*:
$$h(x)=\theta_0 +\theta_1 x_1$$

Example prediction:

| $x$ | size | $y$$ | Price |
|---|---|---|---|
| $x^{(1)}$ |2104| $y^{(1)}$ | 400 |
| $x^{(2)}$ |2500| $y^{(2)}$ | 900 |

**A prediction is defined by the *parameters*** $\theta_0$ and $\theta_1$. And this is a huge reduction in the space of functions

| | size | bedrooms | lot size | | Price |
|---|---|---|---|---|---|
| $x^{(1)}$ | 2104 | 4 | 45k | $y^{(1)}$ | 400 |

**Hypothesis function:**
$$
h(x) = \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \theta_3 x_3
$$

With the convention $x_0 = 1$, written as a summation:
$$
h(x) = \sum_{j=0}^{3} \theta_j x_j
$$


**More notation:**

Parameters = $\theta$ 
$$
\theta = \begin{bmatrix} \theta_0 \\ \theta_1 \\ \theta_2 \\ \theta_3  \end{bmatrix}
$$
Input/features = $x^{(i)}$
$$
x^{(1)} = \begin{bmatrix} x_0^{(1)} \\ x_1^{(1)} \\ x_2^{(1)} \\ x_3^{(1)} \end{bmatrix} = \begin{bmatrix} 1 \\ 2104 \\ 4 \\ 45 \end{bmatrix} 
$$
Target = $y^{(i)}$
$$
y^{(1)} = 400
$$


$(x, y)$ is a training example and $(x^{(i)}, y^{(i)})$ is the $i^{th}$ example.

$$
\{(x^{(i)}, y^{(i)}); i = 1, \ldots, n\}
$$

---

So at the end of the day, for 
$
h_\theta(x) = \sum_{j=0}^{d} \theta_j x_j
$, we want to choose  $\theta$ so that $h_\theta(x) \approx y$.

Least Squares:
$$
J(\theta) = \frac{1}{2} \sum_{i=1}^{n} \left( h_\theta(x^{(i)}) - y^{(i)} \right)^2
$$
- $1/2$ is there to make the derivative cleaner later, just simplifies algebra for when we take the gradient

And we choose $\theta$ to minimize $J$
$$
\theta = \operatorname*{argmin}_{\theta} J(\theta)
$$
- $argmin$ = "the value of $\theta$ that minimzes the function
  - input

> **Gradient — refresher**
>
> The gradient of a function is a vector of its partial derivatives w.r.t. each
> input variable — points in the direction of steepest *increase*.
>
> $$
> \nabla J(\theta) = \begin{bmatrix} \dfrac{\partial J}{\partial \theta_0} \\[4pt] \dfrac{\partial J}{\partial \theta_1} \\[4pt] \vdots \\[4pt] \dfrac{\partial J}{\partial \theta_d} \end{bmatrix}
> $$
>
> - Single variable → just the derivative (a slope)
> - Multiple variables → partial derivative w.r.t. each one, stacked into a vector
> - Gradient points **uphill** (steepest increase); **negative** gradient points **downhill**
>   - The gradient is a *vector* — negating it flips the sign of every component at once,
>     e.g. $\nabla J(\theta) = \begin{bmatrix} 2 \\ -3 \end{bmatrix} \Rightarrow -\nabla J(\theta) = \begin{bmatrix} -2 \\ 3 \end{bmatrix}$
>   - So "negative gradient" isn't a different quantity — it's the same direction info,
>     just reversed for every parameter simultaneously, giving the direction of steepest *decrease*
>   -   In higher dimensions, there's no single **"slope"** since steepness depends on direction — so the gradient is the **natural generalization:** a vector that captures "the slope in every direction at once" by giving you the partial derivative along each axis. Same underlying idea (rate of change), extended to more dimensions.
> - Gradient descent: repeatedly step
>   $$
>   \theta \leftarrow \theta - \alpha \nabla J(\theta)
>   $$
>   Subtracting the gradient moves $\theta$ downhill (equivalent to adding the *negative*
>   gradient); $\alpha$ is the learning rate — how big each step is

---

**Gradient descent — the algorithm**
- We are trying to find the parameter values $\theta$ that make our predictions $h_\theta(x)$ as close as possible to the real answers $y$, across all training examples

Geometric intuition (first-order Taylor approximation): near a point $\theta_0$, the cost
function $J(\theta)$ looks approximately like its tangent line — this is what justifies
"step downhill using the slope":

$$
f(\theta) \approx f(\theta_0) + f'(\theta_0)(\theta - \theta_0)
$$

The slope $f'(\theta_0)$ (or $\nabla J(\theta)$ in higher dimensions) tells you which
direction is downhill *locally* — valid for small steps near $\theta_0$, which is why
gradient descent takes many *small* steps rather than one big jump.

Initialize:
$$
\theta^{(0)} = 0
$$
- This is just an initial guess, could have chosen another value
- No prior information about what the parameters should be
- In this case, all params, $\theta_0^{(0)}, \theta_1^{(0)},... = 0$

Repeat, for $t = 0, 1, 2, \ldots$:
$$
\theta_j^{(t+1)} = \theta_j^{(t)} - \alpha \frac{\partial}{\partial \theta_j} J(\theta^{(t)}) \qquad \text{for } j = 0, \ldots, d
$$

- $\theta^{(t)}$ — the parameter vector at iteration $t$ (superscript is an iteration
  index, not an exponent — same convention as $x^{(i)}$)
- $\alpha$ — the learning rate, controls step size
- $\dfrac{\partial}{\partial \theta_j} J(\theta^{(t)})$ — partial derivative of the cost
  w.r.t. just $\theta_j$, evaluated at the current parameters; every $\theta_j$ updated
  simultaneously
  - Within 1 "step", we take a bunch of ministeps, one ministep for every dimension, or along every "axis"
  - $J(\theta)$ in this case is least squares (as a loss function) since we arleady set it a while back, but this could be any loss function
- Equivalent to the vector form $\theta \leftarrow \theta - \alpha \nabla J(\theta)$,
  written out component-by-component
- Only computing "first-order" information

Stopping: repeat until the gradient is ~0 (converged to a minimum), or for a fixed
number of iterations / until $J(\theta)$ stops meaningfully decreasing.


---

**Computing the derivative of $J(\theta)$**

Using the chain rule on the least squares cost function:

$$
\frac{\partial}{\partial \theta_j} J(\theta^{(t)}) = \sum_{i=1}^{n} \frac{1}{2} \frac{\partial}{\partial \theta_j} \left( h_{\theta^{(t)}}(x^{(i)}) - y^{(i)} \right)^2
$$

$$
= \sum_{i=1}^{n} \left( h_{\theta^{(t)}}(x^{(i)}) - y^{(i)} \right) \frac{\partial}{\partial \theta_j} h_{\theta^{(t)}}(x^{(i)})
$$

- $J$ here is a specific choice of loss function (least squares) — gradient descent
  itself works with any **differentiable loss**, but this derivative is specific to
  least squares since that's what was substituted into $J(\theta)$
- Differentiation distributes over the sum — $\sum_{i=1}^n$ stays outside, unchanged
- The $\frac{1}{2}$ in $J(\theta)$ and the $2$ from the chain rule **cancel exactly** —
  this is *why* the $\frac{1}{2}$ was included in the cost function in the first place
  $h_{\theta^{(t)}}(x^{(i)})$ contributes a derivative term
- Still need to compute $\frac{\partial}{\partial \theta_j} h_{\theta^{(t)}}(x^{(i)})$ itself —
  next step


---

**Deriving $\frac{\partial}{\partial \theta_j} h_\theta(x)$**

Recall $h_\theta(x) = \sum_{k=0}^{d} \theta_k x_k = \theta_0 x_0 + \theta_1 x_1 + \cdots + \theta_d x_d$

Taking the partial derivative w.r.t. $\theta_j$: every term where $k \neq j$ doesn't
contain $\theta_j$ at all, so its derivative w.r.t. $\theta_j$ is 0 — only the
$\theta_j x_j$ term survives:

$$
\frac{\partial}{\partial \theta_j} h_\theta(x) = x_j
$$

**Substituting back into the derivative of $J(\theta)$:**

$$
\frac{\partial}{\partial \theta_j} J(\theta) = \sum_{i=1}^{n} \left( h_{\theta^{(t)}}(x^{(i)}) - y^{(i)} \right) x_j^{(i)}
$$

- The $\frac{\partial}{\partial \theta_j} h_{\theta^{(t)}}(x^{(i)})$ term from before simplifies
  to just $x_j^{(i)}$ — the $j$-th feature of the $i$-th training example
- This is now a **fully concrete formula** — no more unresolved derivatives, just
  known quantities: predictions $h_{\theta^{(t)}}(x^{(i)})$, true labels $y^{(i)}$, and
  feature values $x_j^{(i)}$
- Plugging this into the gradient descent update rule gives the full, usable
  update for linear regression:

>$$
\theta_j^{(t+1)} = \theta_j^{(t)} - \alpha \sum_{i=1}^{n} \left( h_{\theta^{(t)}}(x^{(i)}) - y^{(i)} \right) x_j^{(i)}
$$

**The gradient of $J(\theta)$, in full (all components at once):**

$$
\nabla_\theta J(\theta) = \sum_{i=1}^{n} \left( h_\theta(x^{(i)}) - y^{(i)} \right) x^{(i)}
$$

- This stacks $\frac{\partial}{\partial \theta_j} J(\theta)$ for every $j$ into one
  vector — the sum-form version of the gradient (as opposed to the matrix-form
  version $X^TX\theta - X^Ty$ derived later in the Normal Equations section — same
  gradient, two different ways of writing it)

**In vector notation,** since $j=0,1,2,3,...$
$$
\theta^{(t+1)} = \theta^{(t)} - \alpha \sum_{i=1}^{n} \left( h_{\theta^{(t)}}(x^{(i)}) - y^{(i)} \right) x^{(i)}
$$
Just easier to write, but will be useful for understanding later
- Recall, in a single update, our rule examines *all* $n$ data points which makes this **batch gradient descent**


## Stochastic Gradient Descent
- At times, $n$ can be billions or trillions in modern applications
  - Ex: We try to "predict" every word on the web
  - Obviously computationally expensive

**Idea** Sample a few points (random set, maybe even just one training example) to *approximate* the gradient called **Stochastic Gradient (SGD)**
- SGD is the workhorse of modern ML, like pytorch and tensorflow
- Must truly be random to avoid bias
  - Second statistical assumption we are making, the first was that my training set reflects reality
  - **Batches** are still something the frontier is exploring, it's a statistical assumption and it can go quite deep. Some models, you do choose specific data, say with weird, outstanding features and train it on that.



---

**Stochastic Minibatch**

We randomly select a batch $B \subseteq \{1, \ldots, n\}$ where $|B| < n$.

We approximate the gradient using just those $B$ points, instead of the full
gradient descent sum:

$$
\underbrace{\frac{1}{|B|} \sum_{j \in B} \left( h_{\theta^{(t)}}(x^{(j)}) - y^{(j)} \right) x^{(j)}}_{\text{mini-batch (approximate gradient)}}
\qquad \text{vs.} \qquad
\underbrace{\frac{1}{n} \sum_{j=1}^{n} \left( h_{\theta^{(t)}}(x^{(j)}) - y^{(j)} \right) x^{(j)}}_{\text{full batch gradient descent}}
$$

- $B$ — a randomly chosen subset of training example indices, smaller than the full
  dataset ($|B| < n$)
- Mini-batch sum only runs over the examples in $B$, not all $n$ — cheaper per step
- Both versions are averaged (divided by $|B|$ or $n$ respectively) rather than a raw
  sum — this keeps the step size comparable regardless of batch size
- **Note on notation:** this slide uses $j$ as the *training-example* index (looping
  over data points in $B$), not the *parameter* index like earlier in these notes —
  watch for this index-letter reuse, it means something different here
- Same underlying idea as before: still update all parameters $\theta_0, \ldots, \theta_d$
  each step — what changes is how many examples inform the gradient estimate used to
  take that step

---

**Choosing $B$ — practical notes:**

- If $B = \{1, \ldots, n\}$ (the whole set), mini-batch and full batch gradient
  descent **coincide** — mini-batch is a strict generalization, batch is just the
  special case where $B$ is everything
- Smaller $B$ → lower-quality approximation of the true gradient (higher variance
  per step)
- Despite that, smaller $B$ can still **converge faster** in wall-clock time —
  e.g. when the dataset has a lot of redundancy (many near-duplicate points), a
  small random sample already captures most of the signal, so there's little lost
  by not using the full dataset each step
- In practice, $B$ is chosen based on what runs efficiently on modern hardware
  (GPUs), not purely on statistical grounds — a "what fits/parallelizes well"
  consideration on top of the accuracy tradeoff

---


**SGD update rule (full form)**

$$
\theta^{(t+1)} = \theta^{(t)} - \alpha_B \sum_{j \in B} \left( h_{\theta^{(t)}}(x^{(j)}) - y^{(j)} \right) x^{(j)}
$$

- Same structure as batch gradient descent, but the sum runs only over the mini-batch
  $B$ instead of all $n$ examples
- $\alpha_B$ — the learning rate used specifically for mini-batch — subscripted with
  $B$ deliberately (see note below)


**NB:** the scaling of $|B|$ versus $n$ is "hidden" inside the choice of $\alpha_B$.

- Earlier version had an explicit $\frac{1}{|B|}$ averaging factor out front —
  here that's absent, folded into $\alpha_B$ instead
- i.e. $\alpha_B$ isn't necessarily the same learning rate you'd use for full batch
  gradient descent — it's chosen/tuned to already account for the batch size, so the
  update step ends up appropriately scaled without needing a separate explicit
  $\frac{1}{|B|}$ term

## Normal Equations

**Notation for Least Squares with Linear $h_\theta$**

$$
J(\theta) = \frac{1}{2} \sum_{i=1}^{n} \left( h_\theta(x^{(i)}) - y^{(i)} \right)^2
$$

Convenient matrix notation — stack all training examples into a single matrix/vector:

$$
X = \begin{pmatrix} x^{(1)} \\ x^{(2)} \\ \vdots \\ x^{(n)} \end{pmatrix} \in \mathbb{R}^{n \times (d+1)}
\qquad \text{and} \qquad
y = \begin{pmatrix} y^{(1)} \\ y^{(2)} \\ \vdots \\ y^{(n)} \end{pmatrix} \in \mathbb{R}^{n}
$$

- $X$ — the **design matrix**: each row is one training example's feature vector
  $x^{(i)}$ (which itself has $d+1$ entries, including $x_0 = 1$) — so $X$ has $n$
  rows (one per example) and $d+1$ columns (one per feature, including the intercept)
- $y$ — a column vector stacking all $n$ target values
- This sets up for expressing $J(\theta)$ (and its gradient) in pure matrix/vector
  form, rather than as an explicit sum over $i$ — which is what the normal equations
  derivation will build on next


> **Normal equations — quick reference**
>
> A **closed-form (exact) solution** for the optimal $\theta$ in linear regression —
> no gradient descent, no iteration, just solve directly for the minimum.
>
> **Why it works:** since $J(\theta)$ is convex (bowl-shaped), its minimum is exactly
> where $\nabla J(\theta) = \vec{0}$. Instead of *approaching* that point iteratively,
> solve the equation $\nabla J(\theta) = 0$ algebraically for $\theta$.
>
> Using matrix notation ($X$ = design matrix, $y$ = target vector):
>
> $$
> J(\theta) = \frac{1}{2}(X\theta - y)^T(X\theta - y)
> $$
>
> Setting the gradient to zero and solving gives the **normal equations**:
>
> $$
> X^T X \theta = X^T y
> $$
>
> If $X^TX$ is invertible, solve directly:
>
> $$
> \theta = (X^T X)^{-1} X^T y
> $$
>
> - **"Normal"** = geometric term (perpendicular/orthogonal)
>   - the residual $(X\theta - y)$ ends up orthogonal to the column space of $X$
> - **vs. gradient descent:**
>   | | Normal equations | Gradient descent |
>   |---|---|---|
>   | Type | exact, one-shot | iterative, approximate |
>   | Cost | $O(d^3)$ to invert $X^TX$ — expensive for large $d$ | scales well to large $d$, $n$ |
>   | Generality | only works when a closed form exists (e.g. linear regression) | works for basically any differentiable $J(\theta)$ |

> **Vector/matrix derivatives — quick reference**
>
> For a real-valued matrix function $f : \mathbb{R}^{n \times d} \to \mathbb{R}$
> (takes a whole matrix in, spits out a single number), the **derivative w.r.t. a
> matrix** $A \in \mathbb{R}^{n \times d}$ is itself a matrix of the same shape,
> containing every partial derivative:
>
> $$
> \nabla_A f(A) = \begin{pmatrix}
> \dfrac{\partial}{\partial a_{11}} f(A) & \dfrac{\partial}{\partial a_{12}} f(A) & \cdots & \dfrac{\partial}{\partial a_{1d}} f(A) \\[6pt]
> \dfrac{\partial}{\partial a_{21}} f(A) & \dfrac{\partial}{\partial a_{22}} f(A) & \cdots & \dfrac{\partial}{\partial a_{2d}} f(A) \\[6pt]
> \vdots & \vdots & & \vdots \\[6pt]
> \dfrac{\partial}{\partial a_{n1}} f(A) & \dfrac{\partial}{\partial a_{n2}} f(A) & \cdots & \dfrac{\partial}{\partial a_{nd}} f(A)
> \end{pmatrix}
> $$
>
> - Same idea as the earlier gradient-vector refresher, generalized one level further:
>   before, $\theta$ was a *vector*, so $\nabla J(\theta)$ was a vector of partials.
>   Now $A$ is a *matrix*, so $\nabla_A f(A)$ is a *matrix* of partials — one entry
>   per entry of $A$, same position $(i,j)$
> - The $(i,j)$ entry of $\nabla_A f(A)$ is just $\dfrac{\partial f}{\partial a_{ij}}$
>   — "how much does $f$ change if I nudge just that one entry of $A$"
> - This machinery is what's needed to take the gradient of $J(\theta)$ once it's
>   written in matrix form (e.g. $J(\theta) = \frac{1}{2}(X\theta-y)^T(X\theta-y)$) —
>   sets up for deriving the normal equations cleanly

---

**Deriving the normal equations**

From the matrix form of $J(\theta)$:

$$
\nabla_\theta J(\theta) = \nabla_\theta \frac{1}{2}(X\theta - y)^T(X\theta - y)
$$

Multiplying out (using matrix calculus / the vector derivative rules from before):

$$
\nabla_\theta J(\theta) = X^T X \theta - X^T y
$$

Setting $\nabla_\theta J(\theta) = 0$ (the condition for a minimum, same idea as
before — flat gradient at the bottom of the bowl) and solving for $\theta$, assuming
$(X^TX)^{-1}$ exists:

$$
\theta = (X^T X)^{-1} X^T y
$$

**This is the optimal solution for $\theta$** — exact, closed-form, no iteration.

- Matches exactly what was set up earlier: solve $\nabla J(\theta) = 0$ directly
  rather than approaching it iteratively via gradient descent
- The assumption "$(X^TX)^{-1}$ exists" is doing real work — this requires
  $X^TX$ to be invertible, which fails if features are linearly dependent
  (redundant features) or if there are more features than examples ($d+1 > n$) —
  worth remembering as a limitation of this method


  ---

**Checking this is really a minimum (and when $\theta$ isn't unique)**

Open questions raised: if $(X^TX)^{-1}$ doesn't exist, is $\theta$ still uniquely
defined? (No — in that case there are multiple $\theta$'s achieving the same
minimum $J(\theta)$, typically from redundant/linearly dependent features.)

Why was $\nabla_\theta J(\theta) = 0$ actually a **minimum**? Check the second
derivative (the Hessian, for multivariable functions):

$$
\nabla_\theta^2 J(\theta) = \nabla_\theta \left( X^T X \theta - X^T y \right) = X^T X \succeq 0
$$

- $\nabla_\theta^2 J(\theta)$ — the **Hessian**, the matrix generalization of the
  second derivative $f''(x)$ from single-variable calculus
- $\succeq 0$ means **positive semi-definite** — the matrix analog of "this is a
  non-negative number" — formally, $z^T M z \geq 0$ for every vector $z$
  (equivalently: all eigenvalues $\geq 0$)
- Same logic as the 1D second-derivative test: $f''(x) > 0$ at a critical point
  means it's a minimum (upward-curving, bowl-shaped) — here, $X^TX \succeq 0$ is
  the multivariable version confirming the critical point found by the normal
  equations is genuinely a minimum, not a maximum or saddle point
- Confirms $J(\theta)$ is convex, consistent with everything shown earlier
  (the bowl-shaped picture, guaranteed convergence regardless of gradient descent
  starting point)
