## Supervised Learning Setup


Let's start with some terminology

### Hypothesis/Prediction function:
A function
$$
h : \mathcal{X} \mapsto \mathcal{Y}
$$

- $\mathcal{X}$ is an image, and $\mathcal{Y}$ contains "cat" or "not"
- $\mathcal{X}$ is a text snippet, and $\mathcal{Y}$ contains "hate speech" or "not"
- - $\mathcal{X}$ is house data, and $\mathcal{Y}$ could be the price


### Training set
Set of pairs 
$$
\{(x^{(i)}, y^{(i)}); i = 1, \ldots, n\}
$$

s.t $x^{(i)} \isin \mathcal{X}$ and $y^{(i)} \isin \mathcal{Y}$ for $i=1,...,n$

**Given a training set our goal is to produce a *good* prediction function $h$**
- Defining "good" is a modeling question
- We will want to use $h$ on new data, not on the trainign set

### Reminder
- If $y$ is continuous, then it is called a *regression* problem
- If $y$ is discrete, then it is called a *classification* problem

$$h(x)=\theta_0 +\theta_1 x_1$$

**Hypothesis function:**
$$
h(x) = \theta_0 + \theta_1 x_1 + \theta_2 x_2 + \theta_3 x_3
$$

With the convention $x_0 = 1$, written as a summation:
$$
h(x) = \sum_{j=0}^{3} \theta_j x_j
$$


**More notation:**

Parameters = $\theta$ 
$$
\theta = \begin{bmatrix} \theta_0 \\ \theta_1 \\ \theta_2 \\ \theta_3  \end{bmatrix}
$$
Input/features = $x^{(i)}$
$$
x^{(1)} = \begin{bmatrix} x_0^{(1)} \\ x_1^{(1)} \\ x_2^{(1)} \\ x_3^{(1)} \end{bmatrix} = \begin{bmatrix} 1 \\ 2104 \\ 4 \\ 45 \end{bmatrix} 
$$
Target = $y^{(i)}$
$$
y^{(1)} = 400
$$


$(x, y)$ is a training example and $(x^{(i)}, y^{(i)})$ is the $i^{th}$ example.

$$
\{(x^{(i)}, y^{(i)}); i = 1, \ldots, n\}
$$

---

So at the end of the day, for 
$
h_\theta(x) = \sum_{j=0}^{d} \theta_j x_j
$, we want to choose  $\theta$ so that $h_\theta(x) \approx y$.

Least Squares:
$$
J(\theta) = \frac{1}{2} \sum_{i=1}^{n} \left( h_\theta(x^{(i)}) - y^{(i)} \right)^2
$$
- $1/2$ is there to make the derivative cleaner later, just simplifies algebra for when we take the gradient

And we choose $\theta$ to minimize $J$
$$
\theta = \operatorname*{argmin}_{\theta} J(\theta)
$$
- $argmin$ = "the value of $\theta$ that minimzes the function
  - input

> **Gradient — refresher**
>
> The gradient of a function is a vector of its partial derivatives w.r.t. each
> input variable — points in the direction of steepest *increase*.
>
> $$
> \nabla J(\theta) = \begin{bmatrix} \dfrac{\partial J}{\partial \theta_0} \\[4pt] \dfrac{\partial J}{\partial \theta_1} \\[4pt] \vdots \\[4pt] \dfrac{\partial J}{\partial \theta_d} \end{bmatrix}
> $$
>
> - Single variable → just the derivative (a slope)
> - Multiple variables → partial derivative w.r.t. each one, stacked into a vector
> - Gradient points **uphill** (steepest increase); **negative** gradient points **downhill**
>   - The gradient is a *vector* — negating it flips the sign of every component at once,
>     e.g. $\nabla J(\theta) = \begin{bmatrix} 2 \\ -3 \end{bmatrix} \Rightarrow -\nabla J(\theta) = \begin{bmatrix} -2 \\ 3 \end{bmatrix}$
>   - So "negative gradient" isn't a different quantity — it's the same direction info,
>     just reversed for every parameter simultaneously, giving the direction of steepest *decrease*
>   -   In higher dimensions, there's no single **"slope"** since steepness depends on direction — so the gradient is the **natural generalization:** a vector that captures "the slope in every direction at once" by giving you the partial derivative along each axis. Same underlying idea (rate of change), extended to more dimensions.
> - Gradient descent: repeatedly step
>   $$
>   \theta \leftarrow \theta - \alpha \nabla J(\theta)
>   $$
>   Subtracting the gradient moves $\theta$ downhill (equivalent to adding the *negative*
>   gradient); $\alpha$ is the learning rate — how big each step is

---

**Gradient descent — the algorithm**
- We are trying to find the parameter values $\theta$ that make our predictions $h_\theta(x)$ as close as possible to the real answers $y$, across all training examples

Geometric intuition (first-order Taylor approximation): near a point $\theta_0$, the cost
function $J(\theta)$ looks approximately like its tangent line — this is what justifies
"step downhill using the slope":

$$
f(\theta) \approx f(\theta_0) + f'(\theta_0)(\theta - \theta_0)
$$

The slope $f'(\theta_0)$ (or $\nabla J(\theta)$ in higher dimensions) tells you which
direction is downhill *locally* — valid for small steps near $\theta_0$, which is why
gradient descent takes many *small* steps rather than one big jump.

Initialize:
$$
\theta^{(0)} = 0
$$
- This is just an initial guess, could have chosen another value
- No prior information about what the parameters should be
- In this case, all params, $\theta_0^{(0)}, \theta_1^{(0)},... = 0$

Repeat, for $t = 0, 1, 2, \ldots$:
$$
\theta_j^{(t+1)} = \theta_j^{(t)} - \alpha \frac{\partial}{\partial \theta_j} J(\theta^{(t)}) \qquad \text{for } j = 0, \ldots, d
$$

- $\theta^{(t)}$ — the parameter vector at iteration $t$ (superscript is an iteration
  index, not an exponent — same convention as $x^{(i)}$)
- $\alpha$ — the learning rate, controls step size
- $\dfrac{\partial}{\partial \theta_j} J(\theta^{(t)})$ — partial derivative of the cost
  w.r.t. just $\theta_j$, evaluated at the current parameters; every $\theta_j$ updated
  simultaneously
  - Within 1 "step", we take a bunch of ministeps, one ministep for every dimension, or along every "axis"
  - $J(\theta)$ in this case is least squares (as a loss function) since we arleady set it a while back, but this could be any loss function
- Equivalent to the vector form $\theta \leftarrow \theta - \alpha \nabla J(\theta)$,
  written out component-by-component
- Only computing "first-order" information

Stopping: repeat until the gradient is ~0 (converged to a minimum), or for a fixed
number of iterations / until $J(\theta)$ stops meaningfully decreasing.


---

**Computing the derivative of $J(\theta)$**

Using the chain rule on the least squares cost function:

$$
\frac{\partial}{\partial \theta_j} J(\theta^{(t)}) = \sum_{i=1}^{n} \frac{1}{2} \frac{\partial}{\partial \theta_j} \left( h_\theta(x^{(i)}) - y^{(i)} \right)^2
$$

$$
= \sum_{i=1}^{n} \left( h_\theta(x^{(i)}) - y^{(i)} \right) \frac{\partial}{\partial \theta_j} h_\theta(x^{(i)})
$$

- $J$ here is a specific choice of loss function (least squares) — gradient descent
  itself works with any **differentiable loss**, but this derivative is specific to
  least squares since that's what was substituted into $J(\theta)$
- Differentiation distributes over the sum — $\sum_{i=1}^n$ stays outside, unchanged
- The $\frac{1}{2}$ in $J(\theta)$ and the $2$ from the chain rule **cancel exactly** —
  this is *why* the $\frac{1}{2}$ was included in the cost function in the first place
  $h_\theta(x^{(i)})$ contributes a derivative term
- Still need to compute $\frac{\partial}{\partial \theta_j} h_\theta(x^{(i)})$ itself —
  next step
